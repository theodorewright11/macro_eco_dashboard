# Claude Code instructions for this project

## Read first

Before starting any task, read:

1. `PRD.md` — what the dashboard shows, what's in scope
2. `ARCHITECTURE.md` — how it's built, where things go

If a task is ambiguous about which chart, series or component to touch, **ask before implementing**. Don't guess.

## Update after every change

After any change that affects:

- What the page shows (tiles, charts, series, window options, scope) → update `PRD.md`
- Folder structure, series list, data pipeline, design tokens, commands or deploy → update `ARCHITECTURE.md`

Do this in the same commit. Keep the specs lean: describe the current state, not the history.

## Commit and push after every meaningful change

When a logical unit of work completes (a feature, a bug fix, a new series, a refactor):

1. `git pull` first if you haven't this session: the Monday data-refresh Action pushes to `main`.
2. Run `npm test` and `npm run build` to confirm both pass.
3. `git add` the touched files by specific path. Never `git add -A` or `git add .`.
4. Commit with a one-line message in active voice.
5. `git push`.

A "logical unit of work" is whatever the user asked for, not every file edit. Don't commit half-done work. Don't skip hooks. If the user says not to push, don't.

Never run destructive git commands (`reset --hard`, `push --force`, `branch -D`) unless the user explicitly asks.

## Project rules

- **The repo is public.** Nothing private in code, specs, commits or data: no keys, personal details or client names. There are no secrets today; keep it that way.
- **FRED only, no API key, no backend.** The site stays fully static.
- **Don't hand-edit `public/data/fred/`.** It is generated by `npm run fred` and the weekly Action. Commit regenerated data only when the task is a data refresh.
- **No charting library.** Charts are hand-rolled SVG in `Panel.tsx`.
- **TypeScript** for components. No `any` without a reason.
- **Match the Fika look.** Use the `fika-*` Tailwind colours and `font-grotesk` / `font-figtree`. One colour per series, set in `registry.ts`. Don't add colours or fonts without updating `ARCHITECTURE.md`.
- **Plain language.** Chart titles are questions; subtitles say how to read the chart. Say exactly what a series is (qualifier lines, `USED_AS`), including known quirks.
- **Logic goes in `compute.ts`** (pure, no DOM) with a test in `compute.test.mjs`. Defensive checks only at the boundary (the bundle file).
- **Comments**: only when the why is non-obvious.

## When to ask vs proceed

**Proceed without asking when:** adding a series or chart that fits the existing pattern, fixing a bug, refreshing data, small copy changes.

**Ask first when:** adding a route or page, changing the look (new colour, font, layout pattern), adding a dependency or backend, or touching hosting. Ask clarifying questions as plain text in the chat.

## Don't

- Don't create ad-hoc doc files. Use `PRD.md` and `ARCHITECTURE.md`. (`README.md` is the public readme; keep it in step when the page changes.)
- Don't commit `dist/`, `.astro/` or `node_modules/` (all gitignored).
